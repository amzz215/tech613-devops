## Monitoring 

### Why it is needed

Deploying an app doesn't finish a DevOps role, once users can access the deployed app, it needs to be monitored. 

- I observe if the app is available and responding well 
- I investigate failures or poor perforances
- I adjust capacity when traffic changes

### Monitoring 

Monitoring means collecting and checking information about a running system so I can understand its condition an detect problems 

| Measurement | What it tells me |
|---|---|
| **CPU utilisation** | How much processing capacity is being used |
| **Network traffic** | How much data enters and leaves the VM |
| **Application errors** | Whether requests or operations are failing |

### Dashboards 

A dashboard brings important measurements together so I can quickly understand what's happening 

| Display | What I can see |
|---|---|
| **CPU utilisation graph** | Changes in processing demand |
| **Network In / Out graphs** | Changes in data received and sent |
| **Alarm status** | Whether a configured condition needs attention |

#### Testing

1. Performance testing checks how well a system operates under a workload.
    -  Load testing checks performance under the workload I expect the system to handle. 
    -  Stress testing pushes the system beyond its expected workload to investigate its limits.
    -  Stress testing also tests failure behaviour which is what happens to a system when it can no longer cope with the load
